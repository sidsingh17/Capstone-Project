Diagram 01  ·  Sequence Diagram
RAG Search Flow

This sequence diagram illustrates the complete lifecycle of a natural language search request. The user submits a query through the Frontend SPA, which is forwarded to the FastAPI /search endpoint. The query passes through three-layer Guardrails (length, injection, domain relevance) before being encoded into a 384-dimensional vector. BM25 keyword retrieval and semantic cosine similarity search run in parallel over the corpus, and their ranked lists are merged using Reciprocal Rank Fusion (RRF). A lightweight logistics-aware reranker applies domain-specific boosts before returning the final results.

Key Design: BM25 excels at exact entity matching (supplier IDs, incident types) while semantic search handles conceptual similarity. RRF merges both without requiring score normalisation.

Recommendation Generation Flow

This diagram covers the full Retrieval-Augmented Generation (RAG) pipeline for risk mitigation recommendations. After hybrid search retrieves the top candidate incidents, a token budget manager (tiktoken cl100k_base) ensures the context fits within 8,000 tokens. A multi-dimensional risk scorer computes supplier, inventory, shipment, and demand risk. The structured prompt and risk context are sent to OpenAI GPT-4o-mini (via keygateway), whose output is parsed via regex into five prioritised mitigation steps. Optionally, a LLM-as-Judge evaluates the recommendations across five quality dimensions.

Token Budget
Max 8,000 context tokens — highest-ranked docs fill the budget first
Risk Weights
Supplier 35% · Inventory 30% · Shipment 25% · Demand 10%
Output Format
PRIORITY [1-5]: Action / Timeline / Owner / Expected Impact
LLM Judge Dims
Relevance · Actionability · Completeness · Feasibility · Evidence

Multi-Agent Orchestration with A2A Escalation

Three specialist AI agents — SupplierRiskAgent, ShipmentAnalysisAgent, and InventoryIntelligenceAgent — execute concurrently via ThreadPoolExecutor (max_workers=3). Each agent uses OpenAI function calling (tool use) to query domain-specific data before performing its final analysis. If any agent's risk score exceeds 0.7, it triggers an Agent-to-Agent (A2A) escalation, logging a chain entry and potentially escalating to the Operations Director. The RecommendationAgent then synthesises all findings into a consolidated strategy with proactive disruption alerts.

A2A Escalation Rule: Any specialist agent with risk_score > 0.7 escalates to RecommendationAgent. If the average escalated risk exceeds 0.85, an additional escalation to Operations Director is appended to the chain.

Data Ingestion Pipeline

The ingestion pipeline is triggered automatically at server startup if the vector store is empty, or manually via POST /api/v1/ingest. The pipeline is idempotent — it skips re-ingestion unless force_rebuild=true. The CSV is cleaned, enriched with computed risk scores, converted into structured documents with tiktoken token counts, then embedded in batches using the OpenAI Embeddings API (text-embedding-3-small, 1536-dim) with automatic fallback to sentence-transformers (all-MiniLM-L6-v2, 384-dim) if the gateway is unreachable, and upserted into the numpy-based vector store (persisted as embeddings.npy + documents.json). Finally, the BM25 index is rebuilt in-memory over the full corpus.

Dataset
600 synthetic supply chain incidents · CSV format · 16 fields
Embedding Batch
OpenAI text-embedding-3-small (1536-dim) primary · fallback: all-MiniLM-L6-v2 (384-dim) · 100 docs per DB write
Persistence
documents.json + embeddings.npy in ./chroma_sessions/ directory
Idempotency
Upsert by incident_id · skip if count() > 0 unless force_rebuild

Hybrid Search Decision Flow

This flowchart details the decision logic inside the HybridSearchEngine. A validated query triggers simultaneous BM25 sparse retrieval and semantic dense retrieval (fetch_k = top_k × 3 candidates each). The two ranked lists are merged using Reciprocal Rank Fusion — a rank-position-based fusion that is robust to score scale differences. A final logistics-aware reranker adds field-match boosts before returning the top-k results.

Why RRF over linear combination? BM25 scores are unbounded (corpus-dependent), making direct weighted addition unreliable. RRF uses only rank positions (1/(k+rank)), making it scale-invariant. The constant k=60 dampens sensitivity to top-rank dominance.

Risk Scoring Logic

The risk scoring engine computes a holistic 0–1 risk score across four independent dimensions from the set of retrieved incident documents. Each dimension uses threshold-based scoring derived from aggregate statistics (average delay, average inventory level, delayed shipment ratio, average transport cost). A severity multiplier (1.1× or 1.2×) amplifies scores when critical or high-severity incidents are present. The final weighted sum is clamped to 1.0 and mapped to a risk level.

DimensionWeightInput MetricCritical Threshold
Supplier Risk35%avg_delivery_delay (days)>14 days → 0.90
Inventory Risk30%avg_inventory_level (units)<50 units → 0.95
Shipment Risk25%delayed_ratio (fraction)>60% delayed → 0.85
Demand Risk10%avg_transportation_cost (USD)>$3,000 → 0.70

Multi-Agent Orchestration & A2A Escalation

This flowchart shows how the Orchestrator selects, executes, and coordinates specialist agents. Agent selection uses keyword routing (or include_all_agents=true). Agents run inside a ThreadPoolExecutor with a 60-second timeout per agent. Failed agents produce stub results to prevent cascade failures. The A2A escalation mechanism logs cross-agent notifications when risk thresholds are breached. The RecommendationAgent always runs last to synthesise all findings.

Anomaly Detection Pipeline

The anomaly detection pipeline loads all ingested incident documents, builds a 5-feature numeric matrix, applies StandardScaler normalisation, and fits an IsolationForest model (n_estimators=100). Anomalous records (label = −1) are attributed using per-feature Z-score analysis (threshold: |Z| > 2.5) to identify which metrics drove the anomaly. Separately, a Pearson correlation analysis produces up to five supply chain operational insights from the full dataset.

Feature Matrix
delivery_delay · inventory_level · transport_cost · order_quantity · demand_forecast
IsolationForest
n_estimators=100 · contamination=configurable · random_state=42
Z-Score Attribution
Flag feature if |Z| > 2.5 — direction labelled "high" or "low"
Correlation Thresholds
delay↔cost |r|>0.30 · inv↔delay |r|>0.20 · demand↔cost |r|>0.25
